# Інтеграції з маркетплейсами

CRM — единственный источник правды о товарах, ценах и остатках. Rozetka, Epicentr и Prom получают данные от CRM и возвращают только заказы. Сайт-витрина появится позже и будет таким же получателем данных из CRM, как площадки. План работ — [`../ROADMAP.md`](../ROADMAP.md).

Ниже «сайт» в схеме синхронизации означает CRM: она опрашивает заказы, держит остатки и отдаёт фиды.

Подробности и ссылки на документацию по каждой площадке:

- [rozetka.md](rozetka.md)
- [epicentr.md](epicentr.md)
- [prom.md](prom.md)

## Сравнение площадок

| | Rozetka | Epicentr | Prom |
| --- | --- | --- | --- |
| Формат фида | YML | YML без `shop`/`categories`, коды Epicentr | Prom YML |
| Как читают фид | по URL, раз в час | по URL: цена и наличие раз в сутки (до раза в час через менеджера); контент — ручной импорт в кабинете | по URL: цена и остаток раз в 4 часа (7:00–22:00), контент ночью |
| Количество на складе | `stock_quantity`, обязательно | нет, только статус `in_stock` / `under_the_order` / `out_of_stock` | `quantity_in_stock` + `available` |
| Быстрое обновление цены и остатка | API `PUT /items/mass-update` | API `POST /v1/offers` (закрытая бета) | API `POST /products/edit_by_external_id` |
| Заказы по API | да, опрос `GET /orders/search` | да, опрос списка по дате изменения | да, опрос `/orders/list` |
| Webhooks | нет | нет | нет |
| Срок реакции на новый заказ | 24 часа | 2 часа, иначе автоотмена | не задан жёстко |
| Создание карточек по API | нет, через фид | нет, только фид и кабинет | нет, через фид |
| Ошибки и модерация по API | да | нет, только кабинет | отчёт импорта по API |

## Схема синхронизации

Два канала на каждую площадку:

1. **Фид по URL** — контент: названия uk/ru, описания, фото, характеристики, категории, бренд. Сайт отдаёт три фида из одной базы, у каждой площадки свой генератор.
2. **API** — цена, остаток и заказы. Это быстрый канал, фид для этих полей остаётся страховкой.

Цикл продажи:

1. Каждые 1–2 минуты сайт опрашивает заказы всех трёх площадок по дате изменения.
2. Новый заказ сразу резервирует остаток на сайте, не дожидаясь подтверждения. Отмена или возврат резерв снимают.
3. Сайт пересчитывает доступный остаток и отправляет на все площадки **абсолютное значение**, не разницу. Так повторная отправка не задваивает списание и заодно лечит расхождения.
4. Раз в сутки — сверка цен и остатков с каждой площадкой.

Что настроить на стороне площадок, чтобы не было двойного списания:

- Prom: выключить «Автоматично перераховувати кількість залишків». Не подключать приложение «Робота з Rozetka».
- Rozetka: тип синхронизации прайс-листа «Особистий кабінет (API)», иначе цена и остаток из API перетираются фидом.
- Epicentr: запросить у менеджера доступ к `POST /v1/offers` и автообновление раз в час.

Пока ни на одной площадке нет webhooks, между продажей и обновлением остатка на других площадках остаётся окно в несколько минут. Его закрывает страховой запас: при остатке ниже порога сайт отдаёт площадкам меньшее число или «нет в наличии».

### Количество

Три числа по артикулу:

- **всього** — задаётся вручную на странице «Наявність» (или при импорте);
- **резерв** — сумма позиций в заказах со статусами «Нове» и «Підтверджено» (ещё не отправлено);
- **доступно** = всього − резерв. Именно **доступно** уходит на площадки.

Цикл:

1. Новый заказ → резерв ↑ → пуш абсолютного доступного остатка на все каналы.
2. Подтверждение заказа → остаток не меняем (уже запушили).
3. Отмена → резерв ↓ → пуш.
4. Отправка → всього ↓ и резерв ↓ на число позиций; доступно не меняется.

На площадки:

- Rozetka — `stock_quantity` = доступно;
- Prom — `quantity_in_stock` + `available`;
- Epicentr количества не принимает: доступно > 0 → `in_stock`, иначе `out_of_stock`.

Статус наличия в CRM (`В наявності`, `Закінчується`, `Немає`) — из **доступно** и порога. «Очікується» — ручной флаг при нуле.

### Только украинский

- **Rozetka.** Попросить поддержку перевести фид в статус «український» и отключить автоперевод. Обязательный `<name>` по правилам русский. Как его заполнять в украинском фиде, уточнить у поддержки; до ответа ставим тот же украинский текст, что в `name_ua`.
- **Epicentr.** Передаём только `lang="ua"`, русская версия необязательна. Отключить русскую версию полей — через менеджера.
- **Prom.** `name_ua` и `description_ua` работают только парой. Поля `name` и `description` без суффикса заполняем тем же украинским текстом.

### Цены по площадкам

Базовая цена товара хранится в CRM. Пока сайта нет, «цена сайта» ниже означает эту базовую цену. Когда сайт появится, он получит базовую цену или своё правило, как четвёртая площадка.

Все три площадки получают цену по правилу.

**Rozetka и цена выше сайта.** Rozetka рекомендует ту же цену, что на сайте, но запрещает только цены «необґрунтовано вищі» за вартість у інших точках збуту ([Ціна товару](https://sellerhelp.rozetka.com.ua/p214-price-and-stock.html)). Наценка на размер комиссии Rozetka — наше обоснование; признаёт ли его Rozetka, решает она сама. За «занадто завищені ціни» возможны скрытие товара, ограничение продаж в категории или прекращение сотрудничества. Поэтому наценку для Rozetka держим на уровне комиссии.

Пока сайта нет, «іншими точками збуту» для Rozetka будут Prom и Epicentr. Для товаров, которые продаются только на Rozetka, она сравнивает цену со средней рыночной.

Тип правила:

- точная цена — число вручную;
- выше на % от цены сайта;
- выше на сумму в гривнях.

Округление задаётся вместе с правилом: шаг (по умолчанию 10 грн) и направление (вверх, вниз, к ближайшему). Копеек на площадках нет.

Где задаётся правило, от общего к частному (частное побеждает):

1. по умолчанию для площадки;
2. для категории;
3. для бренда;
4. для конкретного товара.

Что важнее, категория или бренд, — отложено.

Старая цена. Если на сайте есть скидка, то же правило с тем же округлением применяется к старой цене. После округления старая цена должна остаться строго больше новой, иначе её не передаём: Epicentr не публикует товар со старой ценой, равной текущей или ниже. Процент скидки на площадке поэтому может отличаться от сайта на 1–2 пункта.

В админке у товара видно все цены сразу: сайт, Rozetka, Epicentr, Prom, и какое правило дало каждую.

**Резкое изменение цены.** Rozetka считает резкое изменение цены ошибкой: товар становится неактивным, пока цену не подтвердят в кабинете. Справка называет порог «в 3 рази в більшу, чи у 2 рази в меншу сторону» ([Ціна товару](https://sellerhelp.rozetka.com.ua/p214-price-and-stock.html)). Описание API-метода `PUT /items/mass-update`, через который мы шлём цену, — больше чем в 1,5 раза вверх или в 2 раза вниз. До проверки на живом кабинете админка предупреждает по более строгому порогу, 1,5 раза, при сохранении цены сайта или правила, которое меняет цену на Rozetka.

## Категории

У каждой площадки своё дерево. Товар в CRM висит только на **нашей** категории; при выгрузке подставляется внешний ID из маппинга.

| | Rozetka | Epicentr | Prom | Trio Mio (сайт) |
| --- | --- | --- | --- | --- |
| Справочник | API `GET /market-categories/search`, `get-categories-by-parent` | API `GET /v2/pim/categories` (нужен токен) | Файл «Список категорій» из кабинета, API нет | Наше дерево `categories` |
| В фиде | свои `category` + `rz_id` | `category code` конечной | `portal_category_id` листовой | — |
| Только лист | рекомендуется | обязательно `hasChild=false` | обязательно последний уровень | любое |

Модель в CRM:

1. `categories` — наше дерево (оно же меню будущего сайта).
2. `marketplace_categories` — кэш справочника площадки (`marketplace`, `external_id`, `name`, `is_leaf`, `synced_at`).
3. `category_mappings` — `our_category_id` + `marketplace` + `external_category_id` (+ для Epicentr `attribute_set_code`).
4. Кэш атрибутов категории площадки — для обязательности и кодов `param`.

Синк справочников: Rozetka/Epicentr — кнопка «Оновити довідник» (+ по расписанию); Prom — загрузка файла в «Інтеграції».

## Характеристики (фиксированные поля → param площадок)

В UI MVP нет конструктора характеристик и нет вариантов. В карточке — фиксированные поля ([`../admin/product-fields.md`](../admin/product-fields.md)). При генерации фида они мапятся в `param` площадки по справочнику **смапленной** категории.

| | Rozetka | Epicentr | Prom |
| --- | --- | --- | --- |
| Как передаётся | `param name` (+ `paramid`/`valueid`) | `param paramcode` + `valuecode` | `param name` (+ `unit`), значения через `\|` |
| Обязательные | минимум 3 на товар | `isRequired` в attribute set | не обязательны для публикации |
| Справочник | `GET /v1/market-categories/category-options` | `/v2/pim/attribute-sets…` | XML экспорта характеристик из кабинета |
| Если не совпало | не покажется в категории | без кода не примется | «користувацька», не в фильтрах |
| Бренд | `vendor` | код из справочника | только если бренд уже есть в Prom |

Источники: [rozetka.md](rozetka.md) §2.4, [epicentr.md](epicentr.md) §2.3, [prom.md](prom.md) §2.2.

Для админки:

- Фиксированные поля карточки + чек-лист обязательных для включённых каналов.
- Маппинг значений полей → коды/имена площадок — в данных/интеграции; тяжёлый UI зіставлення характеристик — не в первой волне дизайна.
- Загрузка справочников категорий и их атрибутов — этап 0 после доступов.

Список кодов игрушечных категорий без токенов не проверен — первая работа после доступов.

## Поля, которые передать нельзя или можно частично

| Поле | Rozetka | Epicentr | Prom |
| --- | --- | --- | --- |
| Бейджи «Хіт», «Новинка» | нет | нет | тег в YML не описан |
| «−18%» | считает сама из старой цены | считает сама | считает сама; скидка из фида живёт 45 дней, из API 30 |
| «Закінчується» | нет, только число | нет, уходит «в наявності» | не статус, а настройка порога в кабинете |
| «Очікується» | нет | нет (`under_the_order` значит изготовление до 21 дня) | только через API как «Під замовлення» |
| Количество | да | нет, только статус | да |
| Варианты (цвет, размер) | склеивает модерация по характеристике группировки | только вручную в кабинете | `group_id`, нужно приложение «Різновиди», до 3 характеристик |
| Фото | до 15 | лимит в документации не указан | до 10; через API не меняются |
| Бренд | любой, проходит модерацию | только из справочника | только из базы Prom |

Чего сейчас нет в нашей модели товара, а площадки требуют или очень просят:

| Поле | Кому нужно |
| --- | --- |
| Описание | Rozetka и Prom — обязательно; Epicentr — желательно |
| Фото | всем, минимум одно; главное — белый фон, без надписей и плашек |
| Фиксированные атрибуты / param категории | Rozetka — минимум 3; Epicentr — обязательные из attribute set |
| Штрихкод (EAN) | Rozetka — обязателен в части категорий; Epicentr и Prom — по желанию |
| Вес и габариты в упаковке | Rozetka — без них часть отделений и почтоматов недоступна; Epicentr и Prom — по желанию |
| Страна-производитель | Epicentr — служебное поле; Prom — `country` |

Ограничения на текст:

- **Название.** Rozetka — до 255 символов, Epicentr — до 150 и рекомендует шаблон «категорія + особливість + бренд + модель», Prom в API — до 110. В админке нужно одно основное название и необязательное название для каждой площадки.
- **Описание.** Epicentr — до 12 160 символов и только теги `<p> <br> <b> <ul> <li> <table> <tr> <td>`, остальные вырезаются. Rozetka и Prom — до 50 000. Редактор описания в админке стоит ограничить этими тегами.
- **Prom и дефис в названии.** Справка Prom пишет, что название «не должно содержать "-"». Из формулировки неясно, запрещён ли дефис в любом месте или только название из одного дефиса; проверить на тестовой компании Prom.

## Общие решения для данных

- **Артикул.** Rozetka и Epicentr не принимают дефис в ID. Внешний ID — `TM10018`, исходный `TM-10018` уходит в поле артикула. Решить до первой выгрузки: на Epicentr артикул после публикации меняет только менеджер.
- **«Очікується».** Rozetka и Epicentr — «нет в наличии» (у Epicentr «под заказ» означает изготовление до 21 дня). Prom — «Під замовлення» только через API, в YML такого значения нет.
- **Категории.** У каждой площадки свой справочник. В админке: наша категория → листовая категория каждой площадки; обязательные param — из кэша атрибутов смапленной категории.
- **Бренд.** Rozetka требует `vendor`, Epicentr — код бренда из справочника. Предполагается, что бренд есть у каждого товара; обязательность поля в админке — отложено.
- **Фото.** Бейджи «Хіт», «Новинка», «−18%» на фото площадки запрещают. Бейджи живут только на витрине.

## Что в админке

Раздел «Інтеграції» по каждой площадке:

- статус последней выгрузки фида и последнего опроса заказов;
- ошибки модерации и импорта (Rozetka и Prom по API; Epicentr — ссылка в кабинет);
- соответствие категорий; обновление справочников категорий;
- включение и выключение товара на конкретной площадке;
- правила цены для каждой площадки: по умолчанию, по категории, по бренду, по товару; шаг и направление округления;
- очередь отправок цены и остатка с повтором при ошибке.

Только в кабинетах площадок останется: подключение URL фида, смена типа синхронизации, подтверждение «аномальной» цены на Rozetka, группировка вариантов на Epicentr, модерация карточек.

## Открытые вопросы к владельцу

1. Какая доставка на каждой площадке: своя Нова Пошта, доставка Rozetka, фулфилмент?

Отложено:

- страховой запас;
- кто и когда подтверждает заказы и нужно ли автоподтверждение (Epicentr даёт 2 часа);
- порядок правил цены: бренд важнее категории или наоборот;
- обязательность бренда в админке.
