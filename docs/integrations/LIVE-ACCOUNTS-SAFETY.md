# Живые аккаунты площадок — правила безопасности

У клиента уже идут **реальные продажи** на Prom, Rozetka и Epicentr. Каталог, остатки, заказы и статусы на площадках — рабочий бизнес, не песочница. CRM строится с нуля после разрыва со старыми партнёрами; пока продажи сводят вручную в Excel. Ошибки интеграции = потерянные заказы, затёртые остатки, ложные статусы, лишние ТТН.

## Жёсткие правила

1. **По умолчанию только чтение.** Любой вызов API с живыми ключами сначала `GET` / list / status. Запись (`POST`/`PUT`/`PATCH`/`DELETE`, импорт фида, смена статуса заказа, ТТН, правка цены/остатка) — **только после явного «да» в чате**.
2. **Лишний раз переспросить лучше, чем один раз сломать.** Дороже по токенам и времени — нормально. Бездумный пуш запрещён.
3. **Не мешать мок-данные CRM с живым каталогом.** Демо-SKU (`TM-*` из `data/products.json`) на живые кабинеты **не выгружать**, пока не согласован тестовый контур или отдельный тестовый товар.
4. **Не менять статусы заказов «для проверки».** Подтверждение, отмена, «передано в доставку» на проде — только по реальному процессу менеджера.
5. **Не создавать и не отменять ТТН наугад.** Новая Почта / RZ Delivery / Epicentr shipping — только по явной команде и по конкретному `orderId`.
6. **Абсолютные остатки опасны.** Случайный `quantity_in_stock = 0` или `out_of_stock` на всём каталоге остановит продажи. Батч-обновления остатков/цен — только после dry-run списка SKU и подтверждения.
7. **Фид по URL на прод** подключать только когда генератор сверен на тестовом товаре / песочнице. Опции вроде «товары, которых нет в файле → нет в наличии / удалить» на проде **запрещены**, пока не согласованы явно.
8. **Ключи — секреты.** Не коммитить в git, не светить в логах публичного репо, не вшивать в GitHub Pages. Только env / GitHub Actions secrets.
9. **Песочница предпочтительнее прода.** Если у площадки есть test/sandbox company — вся отладка контрактов там. На живом аккаунте — минимальные read-only проверки, потом один согласованный тестовый SKU.
10. **При сомнении — стоп.** Зафиксировать вопрос владельцу/менеджеру; не угадывать enum статусов, причины отмены, коды атрибутов.

## Что можно без спроса (read-only)

- Читать OpenAPI / swagger / справку продавца.
- Писать и обновлять MD-конспекты в `docs/integrations/`.
- Локальный мок CRM (JSON / browserStore) — изолирован от площадок.
- После появления ключей: **только** безопасные GET (профиль, список категорий справочника, один заказ по id для сверки схемы) — и то лучше спросить первый раз.

## Что всегда требует явного «да»

- Любая запись в товар / цену / остаток / фото / характеристики.
- Импорт или смена URL фида.
- Смена статуса заказа, отмена, подтверждение.
- Создание / изменение / удаление ТТН.
- Массовые операции (батч > 1 SKU или > 1 заказа).
- Подключение автоимпорта с опцией «отсутствующие в файле → …».

| --- | --- | --- | --- |
| Prom | **Да** — тестовая компания (+ trial ~7 дн.) | Предпочтительный контур для первых интеграций. Host тот же (`my.prom.ua/api/v1`), другой company token | [`prom-api.md`](prom-api.md) §9 |
| Rozetka | **Нет** отдельного sandbox host | Только прод `api-seller.rozetka.com.ua`; «тестове замовлення» через поддержку — фейковый статус на живом API | [`rozetka-api.md`](rozetka-api.md) §8 |
