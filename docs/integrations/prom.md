# Интеграция с Prom.ua

Исследование для магазина «Лапка»: сайт — единственный источник правды о товарах, Prom — один из трёх маркетплейсов (вместе с Rozetka и Epicentr).

Дата исследования: 7 октября 2026.

Метки достоверности:

- **[ДОК]** — подтверждено официальной документацией Prom (справка support.prom.ua или OpenAPI-спецификация публичного API).
- **[ВЫВОД]** — наш вывод из документации; нужно проверить на тестовой компании.
- **[НЕОФИЦ]** — сторонние источники (блоги, форумы, модули интеграторов); официально не подтверждено.

Номера источников вида [S1] расшифрованы в разделе «Источники» в конце документа.

## 1. Кратко

1. **Формат фида:** лучший вариант — **Prom YML** (`yml_catalog` → `shop` → `categories` + `offers`/`offer`). Это основной формат с самым полным описанием [ДОК, S2]. Формат «XML (Price.ua)» — тот же набор полей с другими названиями тегов (`items`/`item`/`image`/`priceuah`), описан только как список отличий от YML [ДОК, S1]. Excel/CSV подходит только для ручной работы. YML по структуре близок к фидам Rozetka/Epicentr, поэтому генератор на сайте можно сделать общим, а различия держать в адаптерах [ВЫВОД].
2. **Автоимпорт по URL:** ключевые поля (цена, наличие, количество, скидка и связанные с ними) обновляются **раз в 4 часа с 7:00 до 22:00**. Остальные поля и создание новых товаров — **раз в сутки ночью** [ДОК, S3, S4]. Чаще расписание не настраивается.
3. **Публичное API есть:** `https://my.prom.ua/api/v1`, авторизация `Authorization: Bearer <token>`. Токен владелец создаёт сам в кабинете, с правами по группам методов и сроком действия до 1 года [ДОК, S5, S6]. Через API доступно:
   - точечное изменение цены, скидки, наличия, количества и статуса товара, в том числе **по нашему external_id** (`/products/edit_by_external_id`);
   - запуск импорта по URL с выбором обновляемых полей (`/products/import_url`) и получение отчёта (`/products/import/status/{id}`);
   - список заказов с фильтром по дате изменения, получение заказа, смена статуса и отмена с причиной (`/orders/list`, `/orders/{id}`, `/orders/set_status`).

   [ДОК, S6]
4. **Вебхуков в официальной спецификации нет.** Новые заказы получаем только опросом (polling) `/orders/list` [ДОК, S6 — в спецификации нет ни одного webhook/callback].
5. **Rate limit официально не опубликован.** По сторонним данным — от 20 запросов в минуту (форум интегратора, со ссылкой на поддержку Prom) до 1 запроса в секунду (блог) [НЕОФИЦ, S14, S15]. Закладываемся на консервативные **≤ 20 запросов в минуту** и пакетные запросы.
6. **Ловушка двойного списания.** В Prom по умолчанию включено «Автоматично перераховувати кількість залишків»: остаток уменьшается, когда заказ переходит из «Нове» в любой статус, кроме «Виконано» и «Скасовано», и возвращается при отмене [ДОК, S7]. Если сайт сам уменьшает остаток и пушит абсолютное значение в Prom, а Prom ещё раз списывает при принятии заказа, остаток на Prom окажется занижен [ВЫВОД]. Рекомендация: **выключить авто-перерасчёт в Prom** и пушить абсолютные остатки с сайта.
7. **Рекомендуемая схема:**
   - YML-фид с сайта по URL с автоимпортом — для контента и как ежедневная «страховочная» полная сверка;
   - API `edit_by_external_id` — для почти мгновенной отправки остатков и цен;
   - опрос `/orders/list` раз в 1–2 минуты → списание на сайте → отправка нового остатка во все три маркетплейса.

## 2. Рекомендуемый формат фида

### 2.1 Сравнение форматов

| Формат | Где описан | Плюсы | Минусы |
| --- | --- | --- | --- |
| **Prom YML (XML)** | S2 — полное описание всех тегов | Полный набор полей: группы, категория маркетплейса, `oldprice`, `quantity_in_stock`, `param`, `name_ua`/`description_ua`, `group_id` для разновидностей, `gtin`, `regions`. Работает автоимпорт по URL. Близок к YML Rozetka/Epicentr | Нет тега для дат скидки (по ссылке скидка ставится на 45 дней) [ДОК, S2] |
| XML (Price.ua) | S1 — только отличия от YML | Принимается Prom. Если уже есть фид Price.ua — можно переиспользовать | Описан как набор отличий: `catalog` вместо `categories`, `items`/`item` вместо `offers`/`offer`, `image` вместо `picture`, `<available>` отдельным тегом, `priceuah`/`priceusd`. Нового ничего не даёт [ДОК, S1] |
| Excel XLS/XLSX/CSV | S3 и отдельная статья о формате | Удобно для ручной правки | Обязательны поля «Назва_позиції», «Опис», «Ідентифікатор_товару». Без ID повторный импорт **дублирует** товары [ДОК, S3, S8]. Для автоматизации неудобен |
| «Rozetka-YML» | Отдельно в справке Prom не описан | — | Отдельного «формата Rozetka» для импорта в Prom нет. Сам Prom умеет только **экспортировать** прайс для Rozetka через приложение «Робота з Rozetka» [ДОК, S9]. Неописанные теги Prom игнорирует [ДОК, S2], поэтому общий YML с лишними тегами, скорее всего, пройдёт [ВЫВОД] |

**Решение:** отдельный endpoint сайта `/feeds/prom.yml` (UTF-8) в формате Prom YML. Генерируется из БД на лету или регенерируется при каждом изменении товара: фид должен быть актуальным в момент, когда Prom его забирает.

### 2.2 Структура и теги Prom YML [ДОК, S2, если не указано иное]

```text
<?xml version="1.0" encoding="UTF-8"?>          кодировка UTF-8 или windows-1251
<!DOCTYPE yml_catalog SYSTEM "shops.dtd">
<yml_catalog date="...">                        [ВЫВОД: в таблице статьи корневой тег не показан, но есть в DOCTYPE и в примере из FAQ S10]
 <shop>
  <categories>
   <category id="ID_группы" parentId="ID_родителя" portal_id="ID_категории_Prom" portal_url="URL_категории_Prom">Название группы</category>
  </categories>
  <offers>
   <offer id="ID_позиции" available="true|false|" in_stock="true" selling_type="r|w|u|s" group_id="1..999999999" [type="vendor.model"]>
     name / name_ua / typePrefix / model
     categoryId                — обязательно, ID группы из <categories>
     portal_category_id / portal_category_url   — категория маркетплейса (приоритет над portal_id группы)
     price / oldprice (или price_old / old_price) / discount
     currencyId                — UAH, EUR, USD, ...
     quantity_in_stock (или stock_quantity)
     minimum_order_quantity, prices/price/value+quantity — опт
     picture × 1..10
     vendor / vendorCode (или barcode / article) / country
     param name="..." unit="..." — до 100 штук
     dimensions/weight|width|height|length (kg / cm)
     description / description_ua  — HTML только внутри CDATA
     keywords / keywords_ua    — до 1024 символов
     regions/region            — до 3 населённых пунктов
     gtin / mpn
   </offer>
  </offers>
 </shop>
</yml_catalog>
```

Ключевые правила полей:

| Поле | Правило | Статус |
| --- | --- | --- |
| `offer@id` | **Обязательно.** По нему обновляется позиция при следующих импортах. Должен быть уникальным, дубликаты не загрузятся | [ДОК, S2, S11] |
| `name` | Обязательно, если не используется `type="vendor.model"`. Не может состоять только из цифр, не должен содержать «-» и несколько пробелов подряд, нужны буквы | [ДОК, S2, S11] |
| `name_ua` + `description_ua` | Работают **только в паре**: если не заполнено одно поле, украинская версия второго не обновится. То же для `keywords_ua` | [ДОК, S2] |
| `categoryId` | Обязательно, ссылается на `<category id>` | [ДОК, S2, S11] |
| `portal_category_id` | ID листовой категории Prom из файла «Список категорій». Если указать категорию не последнего уровня — ошибка | [ДОК, S2, S10, S12] |
| `price` | Число от 0.01 до 9 999 999 999 — цена со скидкой. Обязательна, если есть `oldprice` | [ДОК, S2] |
| `oldprice` | Цена без скидки. Приоритетнее `price_old`/`old_price`; при наличии `oldprice` тег `discount` игнорируется. Если товар не «в наличии», скидка не применяется и ценой становится `oldprice` | [ДОК, S2] |
| Срок скидки | Даты скидки в фиде не передаются; по ссылке скидка ставится **на 45 дней** | [ДОК, S2] |
| `available` | `"true"` или `"склад"` — В наявності; `"false"` или `""` — Немає в наявності | [ДОК, S1, S2] |
| `in_stock="true"` | «Готово до відправки» — приоритет в выдаче. Доступно **только ТОП-продавцам** (успешные заказы > 80 %, позитивные отзывы > 90 %, включена Пром-оплата) | [ДОК, S2, S13] |
| `quantity_in_stock` | Целое. Обновляется, только если в настройках импорта отмечено поле «Кількість» (для быстрого 4-часового импорта — «Наявність») | [ДОК, S2, S7] |
| `picture` | 1–10 ссылок, JPG/GIF/PNG, ≤ 10 МБ; картинки грузятся отдельной очередью. Дубли Prom отсеивает сам | [ДОК, S2, S3] |
| `vendor` | Импортируется, **только если бренд уже есть в базе производителей Prom** | [ДОК, S2] |
| `vendorCode` | Артикул: до 25 символов (цифры, кириллица, латиница, `- _ . /` и пробел). Приоритетнее `barcode` и `article` | [ДОК, S2] |
| `param` | До 100 на позицию. Название и единица измерения должны **точно совпадать** с характеристиками категории в кабинете. Несколько значений разделяются `\|` | [ДОК, S2] |
| `description` | **Обязательно.** HTML — только в `<![CDATA[...]]>` | [ДОК, S2] |
| Спецсимволы | `" & > < '` нужно экранировать; непечатаемые символы запрещены | [ДОК, S2] |

### 2.3 Язык (uk/ru)

- В фиде есть пары `name`/`name_ua`, `description`/`description_ua`, `keywords`/`keywords_ua` [ДОК, S2]. По смыслу «базовые» поля без суффикса — это русская версия [ВЫВОД].
- Если у нового товара заполнена только одна языковая версия, Prom автоматически переводит вторую; это может занять несколько часов [ДОК, S16].
- Если двуязычность выключена, RU-поля в файле импорта должны быть заполнены украинским текстом — этого требует закон о языке [ДОК, S16].
- В API: заголовок `X-LANGUAGE: uk|ru|en|ro|kk`, по умолчанию `uk`; методы `/products/translation` (GET/PUT) [ДОК, S6].
- **Рекомендация:** у «Лапки» контент на украинском, поэтому заполнять и `name_ua`/`description_ua`, и `name`/`description` (одинаковым украинским текстом или русским переводом — решает владелец, см. открытые вопросы).

### 2.4 Разновидности (варианты)

- Нужен подключённый веб-додаток «Різновиди»; без него разновидности не импортируются, а при включённом приложении считается, что они есть в файле [ДОК, S3, S17].
- В YML разновидности — это `offer` одной группы с одинаковым `group_id`. Первый offer — основной [ДОК, S17].
- Разновидности строятся максимум по **3 характеристикам** с одиночным (не множественным) выбором. Значения должны быть заполнены и уникальны. Ошибка в основном товаре блокирует всю группу [ДОК, S17].
- Через API `quantity_in_stock` недоступен для разновидностей, которые наследуют наличие [ДОК, S6].
- В каталоге «Лапки» вариантов пока нет; если появятся (цвет/размер), формат готов.

### 2.5 Соответствие модели «Лапки» полям Prom

| Поле «Лапки» | Prom YML | Prom API (`edit_by_external_id`) | Примечание |
| --- | --- | --- | --- |
| SKU `LP-10018` | `offer@id` и `vendorCode` | `id` (external_id) | Что `offer@id` из YML становится `external_id` в API — [ВЫВОД], проверить на тестовой компании. Если Prom не примет буквенно-цифровой `offer@id`, взять числовую часть `10018` |
| Название | `name_ua` (+ `name`) | `name` (≤ 110 символов) + `/products/translation` | Лимит 110 символов указан для API [ДОК, S6]; для YML лимит не указан |

| Категория | `categoryId` (группа сайта) + `portal_category_id` | — (в API нет) | Сопоставление наших категорий с ID Prom ведём в админке |
| Возраст | `param name="Вік дитини"` (пример) | — | Точное название характеристики берётся из категории Prom [ВЫВОД] |
| Цена / старая цена | `price` / `oldprice` | `price` / `oldprice` | В API: `oldprice` требует `price`, скидка ставится на 30 дней; `oldprice` и `discount` вместе нельзя [ДОК, S6] |
| Остаток | `quantity_in_stock` | `quantity_in_stock` | — |
| «В наявності» | `available="true"` | `presence: available` | — |
| «Закінчується» | `available="true"` + малый `quantity_in_stock` | то же | В Prom это не отдельный статус, а режим отображения по порогу в «Налаштування → Залишки товарів» [ДОК, S7] |
| «Немає в наявності» | `available="false"` | `presence: not_available` | — |
| «Очікується» | **нет явного значения в YML** | `presence: order` («Під замовлення») | В YML «Під замовлення» не описано [ДОК — отсутствует в S2]. Через API — `order` [ДОК, S6]. Товары «Під замовлення» не попадают в экспорт для Rozetka [ДОК, S9] |
| Бейдж «Хіт» | не описан | — | В `updated_fields` импорта есть значение `labels` [ДОК, S6], но тег в YML не описан — открытый вопрос |
| Фото | `picture` × до 10 | — (в API редактирования нет) | Фото меняются только через импорт |

### 2.6 Минимальный валидный пример (LP-10018)

Значения, которые нужно подставить из справочников Prom, помечены `ЗАМЕНИТЬ`. Остаток `12` условный: в sample-catalog количества нет.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE yml_catalog SYSTEM "shops.dtd">
<yml_catalog date="2026-10-07 21:00">
  <shop>
    <name>Лапка</name>
    <company>Лапка</company>
    <url>https://lapka.example.ua</url>
    <currencies>
      <currency id="UAH" rate="1"/>
    </currencies>
    <categories>
      <!-- portal_id: ID листовой категории Prom из «Списку категорій» — ЗАМЕНИТЬ -->
      <category id="10" portal_id="0000">Конструктори</category>
    </categories>
    <offers>
      <offer id="LP-10018" available="true" selling_type="r">
        <name>Конструктор LEGO City «Пожежна частина»</name>
        <name_ua>Конструктор LEGO City «Пожежна частина»</name_ua>
        <categoryId>10</categoryId>
        <price>1890</price>
        <oldprice>2290</oldprice>
        <currencyId>UAH</currencyId>
        <quantity_in_stock>12</quantity_in_stock>
        <picture>https://lapka.example.ua/media/products/LP-10018/1.jpg</picture>
        <vendor>LEGO</vendor>
        <vendorCode>LP-10018</vendorCode>
        <!-- name/unit характеристики копируются из категории Prom — ЗАМЕНИТЬ при необходимости -->
        <param name="Вік дитини">6–12 років</param>
        <description><![CDATA[<p>Конструктор LEGO City «Пожежна частина» для дітей 6–12 років.</p>]]></description>
        <description_ua><![CDATA[<p>Конструктор LEGO City «Пожежна частина» для дітей 6–12 років.</p>]]></description_ua>
      </offer>
    </offers>
  </shop>
</yml_catalog>
```

Блок `name`/`company`/`url`/`currencies` в описании формата не значится обязательным, но присутствует в примере Prom [ДОК, S10]. Оставляем его ради совместимости со стандартом YML и фидами других маркетплейсов.

## 3. Механизмы обновления и частота

### 3.1 Импорт по ссылке с автообновлением (кабинет) [ДОК, S3, S4]

- Раздел «Товари та послуги → Імпорт» → способ «Посилання». Можно указать до 4 ссылок, они обрабатываются по очереди.
- **Быстрый импорт («раз на 4 години»):** обновляет «Ціна», «Знижка», «Наявність», «Кількість» и связанные поля:
  - с ценой — оптовые цены, валюта, единица измерения, минимальный заказ;
  - с наличием — «Готово до відправки», срок поставки, срок ожидания, количество.

  Работает **с 7:00 до 22:00**; время старта зависит от нагрузки на сервер. Если не отмечено «Наявність», количество быстрым импортом не обновится.
- **Остальные поля и создание новых товаров** — раз в сутки ночью.
- Периодический импорт настраивается **не чаще 1 раза в 24 часа**; часто обновляются только ключевые поля.
- **Автоотключение:** при ошибках доступа к файлу, неверном формате или пустом файле на 4-й день приходит письмо, а на 6-й день периодический импорт отключается. Успешный импорт обнуляет счётчик ошибок.
- Флажки «Оновити примусово» и «Тільки оновлення» работают **только при ручном запуске** и не сохраняются для периодического импорта.
- Для всех товаров из файла дата обновления меняется на дату импорта.

### 3.2 Настройки импорта [ДОК, S3; API — S6]

| Настройка в кабинете | Параметр API (`import_url` / `import_file`) | Значения |
| --- | --- | --- |
| «Інформація, яку потрібно оновити» | `updated_fields[]` | `name, sku, price, images_urls, presence, quantity_in_stock, description, group, keywords, attributes, discount, labels, gtin, mpn, name_ua, keywords_ua, description_ua`. По умолчанию `price, presence` |
| «Оновити примусово» | `force_update` | Обновить все товары, а не только изменившиеся с прошлого импорта |
| «Завантажити позиції "В наявності"» | `only_available` | В API: только «В наявності» и «Під замовлення» |
| «Тільки оновлення» | `only_update` | Не создавать новые товары |
| «Статус товарів, яких немає в файлі» | `mark_missing_product_as` | `none`, `not_available`, `not_on_display` (скрыть), `deleted` |

Рекомендуемые значения: `mark_missing_product_as = not_available`. Удаление (`deleted`) не используем: удалённые группы не восстанавливаются [ДОК, S10].

### 3.3 Лимиты импорта [ДОК, S3, S10]

- До **100 000 новых товаров в месяц** через импорт.
- Ручной импорт — до **10 раз в сутки**, дальше каждый следующий запуск не раньше чем через 2 часа после предыдущего. Распространяется ли это на `/products/import_url` — **неизвестно**.
- Процесс импорта длится максимум **2 часа**, потом считается неудачным.
- Если файл стоит в очереди больше 3 часов, нужно писать в поддержку.
- Рекомендуемый размер YML — **до 180 МБ**; поддерживаются ZIP и GZIP.
- Новые товары при повторном импорте обязательно должны быть с группой.
- При высокой нагрузке запуск импортов может временно ограничиваться.

### 3.4 Запуск импорта через API [ДОК, S6]

- `POST /products/import_url` с JSON `{url, force_update, only_available, only_update, mark_missing_product_as, updated_fields}` → ответ `{id, status: success|error}`.
- `POST /products/import_file` — multipart: `file` плюс `data` с теми же настройками в JSON. Принимает xls, csv, xlsx, xml.
- `GET /products/import/status/{id}` → `status` (`SUCCESS`, `PARTIAL`, `FATAL`), счётчики `created`, `updated`, `not_changed`, `not_in_fle`, `with_errors_count`, `total` и т. д., плюс `errors[]` по этапам (`download`, `store_file`, `validation`, `import`, `download_images`).
- Это позволяет **по кнопке в админке «Лапки»** запускать внеплановый полный или частичный импорт и показывать отчёт об ошибках у нас. Например, «отправить на Prom сейчас» после правки описаний.

### 3.5 Частичное точечное обновление через API (быстрее всего) [ДОК, S6]

- `POST /products/edit_by_external_id` — тело: **массив** объектов `{id: "<external_id>", price?, oldprice?, discount?, presence?, quantity_in_stock?, status?, name?, description?, keywords?, prices?}`.
- `POST /products/edit` — то же по внутреннему `id` Prom; дополнительно доступны `in_stock` («Готово до відправки») и `regions`.
- Ответ: `{processed_ids[], errors{}}`.
- Пакетность подтверждена: тело — массив. **Максимальный размер пакета в спецификации не указан**; встречается цифра «до 100 товаров» [НЕОФИЦ, S15].
- Через API **нельзя** менять фото, категорию, группу, бренд и характеристики — это только импорт или кабинет [ДОК, S6: этих полей нет в request body].

## 4. Возможности API

База: `https://my.prom.ua/api/v1`. Заголовки: `Authorization: Bearer <token>`, опционально `X-LANGUAGE`. Все даты в **UTC**, формат фильтров — `2015-04-28T12:50:34` [ДОК, S5, S6].

**Токен** [ДОК, S5]:

- Создаётся в «Налаштування → Управління API-токенами» владельцем или администратором компании.
- Срок действия — от 1 дня до 1 года; за 30 и за 7 дней до окончания приходят уведомления.
- Права — по группам: «Замовлення і повідомлення», «Продукти та групи», «Клієнти», «Налаштування». Уровни: нет доступа (403), только чтение (POST → 403), чтение и запись.
- Просроченный или удалённый токен → 401.
- В документации API (S6) сказано «токен выдаёт сотрудник портала» — это устаревшая формулировка; сейчас токен создаётся самостоятельно [ДОК, S5, S18].

**Песочница:** отдельная компания с тестовым периодом; токен для неё — по запросу к менеджеру [ДОК, S6].

**Статус API:** формально «версия 1.0, закрытый бета-тест» [ДОК, S6]. Фактически им пользуется много интеграторов [НЕОФИЦ].

**Чего в API нет** [ДОК — отсутствует в S6]:

- вебхуков и callback-подписок;
- создания товара через API (только `edit` существующих; новые товары — через импорт);
- изменения фото, категории, бренда, характеристик (только импорт или кабинет);
- создания или удаления групп (только `list` и `translation`);
- настроек остатков и настроек импорта по ссылке (расписание задаётся в кабинете);
- опубликованного rate limit.

**Rate limit** [НЕОФИЦ]:

- На форуме OneBox поддержка Prom, по словам участников, назвала лимит 20 запросов в минуту; при превышении токен блокировался примерно на 2 часа [S14].
- Блог REVENZA пишет про 1 запрос в секунду и ответ 429 [S15].
- В модуле Odoo заявлена «поддержка webhook» — официально не подтверждено [S19].

**Вывод:** проектируем под ≤ 20 запросов в минуту на токен, с пакетами и экспоненциальной паузой. Точный лимит уточняем в api@prom.ua.

## 5. Заказы и синхронизация остатков

### 5.1 Как Prom ведёт остатки сам [ДОК, S7]

- «Налаштування → Залишки товарів» → «Облік залишків».
- **«Автоматично перераховувати кількість залишків»** включено по умолчанию: остаток списывается, когда заказ уходит из «Нове» в любой статус, кроме «Виконано» и «Скасовано»; при отмене возвращается.
- «Приймати замовлення… за відсутності» — если выключено, покупатель не сможет положить в корзину больше остатка.
- При нулевом остатке товар автоматически переводится в «Немає в наявності» или «Під замовлення» — по настройке.
- Отображение остатков: точное число, «В наявності» / «Закінчується» по порогу X или «Більше / менше X од».

### 5.2 Статусы заказа [ДОК, S6, S20]

| Кабинет | API `status` | Комментарий |
| --- | --- | --- |
| Нове | `pending` | Новый, требует обработки |
| Оплачено | `paid` | Оплачен покупателем (Пром-оплата) |
| Прийнято | `received` | Продавец принял |
| Виконано | `delivered` | Выполнен |
| Скасовано | `cancelled` в ответе, `canceled` в запросе `set_status` | Написание различается в спецификации — проверить на тесте [ДОК, S6] |
| Чернетка | `draft` | — |
| Свой статус | `custom-{id}` | Через `custom_status_id` |

- Источник заказа — поле `source`: `portal`, `company_site`, `company_cabinet`, `mobile_app`, `bigl` [ДОК, S6].
- Позиции заказа содержат `external_id`, `sku`, `quantity`, `price` — этого достаточно, чтобы сопоставить заказ с SKU «Лапки» [ДОК, S6].
- Есть `cancellation{title, initiator: company|user|system}` и `cpa_commission` [ДОК, S6].

### 5.3 Рекомендуемый поток [ВЫВОД]

```text
[Сайт = мастер остатков]
     │ 1. Изменение остатка/цены (продажа на сайте, Rozetka, Epicentr, Prom, ручная правка)
     ▼
 Очередь sync-задач (дебаунс 5–30 с, пачки)
     ├─► Prom:     POST /products/edit_by_external_id [{id:"LP-10018", quantity_in_stock:11, presence:"available"}]
     ├─► Rozetka:  (см. rozetka.md)
     └─► Epicentr: (см. epicentr.md)

[Опрос Prom раз в 60–120 с]
 GET /orders/list?last_modified_from=<курсор UTC − запас>&sort_dir=asc&limit=N
     │ дедупликация по order.id + status (идемпотентно)
     ├─ новый заказ (pending/paid) → резерв/списание на сайте по products[].external_id или sku
     │                               → шаг 1 (пуш нового остатка во все маркетплейсы)
     ├─ cancelled                  → возврат на сайте → шаг 1
     └─ товара уже нет (оверселл)  → POST /orders/set_status {status:"canceled", cancellation_reason:"not_available"}
                                      (или решение менеджера в админке)

[Админка «Лапки»] «Прийняти» / «Виконано» → POST /orders/set_status {ids, status:"received"|"delivered"}
                   ТТН → POST /delivery/save_declaration_id

[Страховка] YML-фид по ссылке: остатки и цены раз в 4 часа (7–22), остальное ночью;
            ежесуточная сверка GET /products/list?last_modified_from=… против БД сайта.
```

Ключевые решения:

1. **Выключить в Prom «Автоматично перераховувати кількість залишків»** [ВЫВОД из S7]. Иначе:
   - сайт списывает 1 и пушит `quantity_in_stock = 11`;
   - позже, когда заказ переходит в «Прийнято», Prom сам списывает ещё 1 → 10;
   - Prom показывает заниженный остаток до следующего пуша или автоимпорта.

   Альтернатива — оставить авто-перерасчёт как защиту в окне между заказом и нашим пушем и **никогда не пушить остаток по товарам с открытыми Prom-заказами**. Это сложнее, рекомендуем первый вариант.
2. **Пушить абсолютные значения**, а не дельты: операция идемпотентна и устойчива к повторам.
3. **Курсор по `last_modified_from`**, а не только по `date_from`: так ловим и смену статусов, например отмену покупателем. Брать запас в несколько минут из-за UTC и задержек.
4. **Окно оверселла.** Продажа на Rozetka через минуту отражается на Prom только после нашего опроса Rozetka и пуша в Prom. При лимите ≤ 20 запросов в минуту реальная задержка — 1–3 минуты. Для товаров с малым остатком («Закінчується», ≤ 2 шт.) можно держать на маркетплейсах страховой резерв, например показывать остаток минус 1 [ВЫВОД].
5. **Не включать в Prom приложение «Робота з Rozetka»**: оно подтягивает заказы Rozetka в кабинет Prom [ДОК, S9]. Это создаст второй путь заказа и риск двойной обработки, а Rozetka мы интегрируем напрямую. Попадают ли такие заказы в `/orders/list`, неизвестно: в enum `source` значения rozetka нет.
6. **Бюджет запросов:** опрос заказов раз в минуту — 1–2 запроса; пуш остатков пачками; итого заметно меньше 20 в минуту в обычном режиме. Для массового переценивания использовать `import_url` с `updated_fields=[price, discount]`, а не тысячи `edit`.

## 6. Ошибки и отчёты импорта

- **Через API:** `GET /products/import/status/{id}` возвращает статус и ошибки по этапам — только для импортов, запущенных через API, по полученному `id` [ДОК, S6]. Для `edit` и `edit_by_external_id` ошибки приходят прямо в ответе (`errors` с ID товаров) [ДОК, S6].
- **Только в кабинете:** вкладка «Звіт по імпорту» для импорта по ссылке, запущенного по расписанию; список критичных и некритичных ошибок; кнопки «Пропустити помилки» и «Продовжити з помилками» [ДОК, S3, S11]. Получить через API отчёт **периодического** импорта (у него нет нашего `id`) нельзя — такой возможности в спецификации нет [ДОК — отсутствует в S6].
- Письма о неудачном автоимпорте на 4-й день и об отключении на 6-й [ДОК, S3].
- Частые критичные ошибки: пустой файл; недоступные картинки; нет или дублируется ID; некорректное название; нет ID категории; категория не последнего уровня; ошибки в основном товаре блокируют все разновидности [ДОК, S10, S11, S17].
- **Рекомендация:** в админке «Лапки» показывать статус «Prom: синхронизировано в 09:40 / ошибка …» на основе собственных вызовов API и `import/status`. Плюс раз в сутки сверять `GET /products/list?last_modified_from=` с БД.

## 8. Открытые вопросы к владельцу бизнеса

1. **Тариф Prom и статус продавца.** Платный пакет? Экспорт из кабинета доступен только на платном [ДОК, S8]. Есть ли статус ТОП-продавца для «Готово до відправки»?
2. **Языки.** Двуязычная витрина на Prom (uk + ru) или только украинский? От этого зависит, что писать в `name`/`description`.
3. **«Очікується».** Показывать на Prom как «Під замовлення» (можно купить с ожиданием) или как «Немає в наявності»? В YML «Під замовлення» не описано: либо пушим через API (`presence: order`), либо скрываем.
4. **Авто-перерасчёт остатков в Prom.** Согласны выключить и доверить остатки только сайту?
5. **Страховой резерв.** Показывать ли на маркетплейсах остаток минус N для товаров «Закінчується», чтобы снизить риск оверселла между площадками?
6. **Кто принимает заказы Prom:** менеджер в админке «Лапки» (статусы уходят в Prom через API) или по-прежнему в кабинете Prom? Нужна ли автоматическая отмена при оверселле с причиной `not_available`?
7. **Скидки и старая цена.** На Prom скидка из фида живёт 45 дней, из API — 30 дней (потом её надо продлевать повторной отправкой). Нужны ли акции с точными датами начала и окончания? Тогда только через API `discount{date_start, date_end}`.
8. **Бейджи («Хіт»).** Нужны ли они на Prom? В YML тег для ярлыков не описан — уточнять в поддержке.
9. **Категории и характеристики.** Кто сопоставляет наши категории с ID категорий Prom и названиями характеристик (например, «Вік дитини»)? Предлагаем таблицу соответствия в админке.
10. **Разные цены на площадках.** Нужна ли отдельная цена для Prom (наценка на комиссию) или везде цена сайта?
11. **Тестовая компания.** Готовы ли зарегистрировать песочницу Prom для проверки форматов, external_id и статусов до запуска?

**Технические вопросы в api@prom.ua:**

- точный rate limit;
- максимальный размер пакета `edit_by_external_id`;
- распространяется ли лимит «10 импортов в сутки» на `import_url`;
- появятся ли вебхуки;
- совпадает ли `offer@id` из YML с `external_id` в API;
- написание статуса `canceled` / `cancelled`.
