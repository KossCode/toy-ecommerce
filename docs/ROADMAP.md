# План работ

## Решение

Первой делаем собственную CRM — админку, которая хранит товары, остатки, цены и заказы и синхронизирует их с Rozetka, Epicentr и Prom. Магазин начинает продавать на маркетплейсах без сайта. Сайт-витрина Trio Mio строится потом поверх API той же CRM и считается четвёртым каналом.

Почему своя, а не готовая (KeyCRM, SalesDrive, OneBox):

- нет ежемесячной подписки, платим за хостинг;
- полный контроль над тем, как передаются описания, поля, цены и остатки;
- функциональность не ограничена вендором, дорабатываем сами.

Цена решения: время разработки и поддержка интеграций. Площадки меняют API и правила, чинить это нам.

## Принципы

- **CRM — единственный источник правды.** Площадки и будущий сайт только получают данные и возвращают заказы.
- **Сначала API, потом экраны.** Админка — первый клиент API, сайт — второй.
- **Одна площадка до конца, потом следующая.** Каждая: каталог, цены, остатки, заказы. Затем следующая.
- **Разделы на потом видны в навигации**, но открывают заглушку, пока не реализованы.

## Порядок площадок

1. **Prom.** Каталог клиента уже живёт там и уходит на Rozetka; API мягче; есть тестовая компания.
2. **Rozetka.** Полный API заказов и остатков; строже модерация; минимум 3 характеристики.
3. **Epicentr.** Коды характеристик; 2 часа на подтверждение заказа; обновление цены/наличия в закрытой бете.

## Этапы

### 0. Доступы и справочники

- Кабинеты и токены API трёх площадок; для Epicentr — доступ к `POST /v1/offers` и `/v2/pim/*`.
- Ключ API Новой Почты (подключение ТТН — этап после запуска продаж).
- Выгрузить/закэшировать справочники категорий (и атрибутов категорий) игрушечных веток.
- Rozetka: попросить поддержку перевести фид в режим «український».
- Правило ID: `TM-10018` → `TM10018` на Rozetka/Epicentr ([integrations/README.md](integrations/README.md)).
- Стек: PostgreSQL; файлы — локально сейчас, S3 позже.

### 1. Каталог

- Товары: фиксированные поля из [`admin/product-fields.md`](admin/product-fields.md); статус черновика; тумблеры каналов.
- Без вариантов и без свободного конструктора характеристик.
- Количество: `всього`; резерв считает система; `доступно` уходит на площадки.
- Своё дерево категорий + маппинг на категории площадок.
- Первичная загрузка — из существующего каталога Prom (CSV/YML), открытый вопрос по объёму.
- Готовность к площадке: список незаполненных обязательных полей.

### 2. Выгрузка на первую площадку

- Соответствия категорий (и кодов атрибутов под капотом).
- Правила цены площадки с округлением.
- Фид по URL + API цены и остатка.
- Включение/выключение товара на площадке.
- Статус выгрузки и ошибки в «Інтеграції».

### 3. Заказы

- Опрос заказов раз в 1–2 минуты, единая лента.
- Резерв при новом заказе; снятие при отмене; пуш доступного остатка на все каналы.
- Единые статусы CRM ↔ статусы площадок.
- Подтверждение и отмена из CRM.
- Уведомление о новых заказах (критично для Epicentr — 2 часа).

**Запуск продаж на первой площадке.**

### 4. Следующие площадки

Этапы 2–3 для Rozetka, затем Epicentr.

### 5. Новая Почта и доставка

- Создание ТТН из заказа; номер уходит на площадку.
- В карточке заказа: номер ТТН, статус доставки из API НП (если отдаёт), ссылка на трекинг.
- В дизайне заказов ТТН закладываем сразу; реализация — после стабилизации продаж.

### 6. Разделы на потом

- **Клієнти**, **Акції**, **Аналітика** — дизайн заранее, реализация позже.
- **Контент** — вместе с сайтом.
- Платежные системы — после сайта или по необходимости площадок.

### 7. Сайт-витрина

По пакету [`design/`](design/README.md). Категории сайта = наше дерево CRM. Сайт — четвёртый канал в ленте заказов.
