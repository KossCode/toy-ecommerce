# План работ

## Решение

Первой делаем собственную CRM — админку, которая хранит товары, остатки, цены, заказы и клиентов и синхронизирует их с Rozetka, Epicentr и Prom. Магазин начинает продавать на маркетплейсах без сайта. Сайт-витрина строится потом поверх API той же CRM.

Почему своя, а не готовая (KeyCRM, SalesDrive, OneBox):

- нет ежемесячной подписки, платим за хостинг;
- полный контроль над тем, как передаются характеристики, описания, цены и остатки;
- функциональность не ограничена вендором, дорабатываем сами.

Цена решения: время разработки и поддержка интеграций. Площадки меняют API и правила, чинить это нам.

## Принципы

- **CRM — единственный источник правды.** Площадки и будущий сайт только получают данные и возвращают заказы.
- **Сначала API, потом экраны.** Админка — первый клиент API, сайт — второй. Всё, что делает админка, доступно через API.
- **Одна площадка до конца, потом следующая.** Каждая площадка подключается целиком: каталог, цены, остатки, заказы, отправка. Только после этого — следующая.
- **Разделы на потом проектируются сразу.** Клиенты, акции, аналитика есть в навигации и в дизайне, но реализуются позже. Модель данных с первого дня учитывает их и витрину.

## Порядок площадок

1. **Prom.** Самый терпимый: несовпавшие характеристики не ломают товар, токен API владелец выпускает сам, есть тестовая компания.
2. **Rozetka.** API заказов и остатков полный, справочники характеристик по API, но модерация строже и минимум 3 характеристики.
3. **Epicentr.** Самый жёсткий: характеристики только кодами, 2 часа на подтверждение заказа, метод обновления цены и наличия в закрытой бете.

Порядок — предложение. Если на одной из площадок у магазина уже есть кабинет и продажи, её разумно поставить первой.

## Этапы

### 0. Доступы и справочники

- Кабинеты продавца на трёх площадках, доступы к API: логин Rozetka, токен Epicentr с запросом доступа к `POST /v1/offers`, токен Prom.
- Ключ API Новой Почты.
- Выгрузить справочники категорий и характеристик игрушечных категорий каждой площадки.
- Rozetka: попросить поддержку перевести фид в режим «український».
- Зафиксировать правило ID товара: `TM-10018` → `TM10018` ([integrations/README.md](integrations/README.md), «Общие решения для данных»).
- Выбрать стек и хостинг.

### 1. Каталог

Без этого нечего выгружать.

- Товары: артикул, название, описание, фото, бренд, категория, штрихкод, вес и габариты, страна-производитель.
- Количество по артикулу, базовая цена, старая цена.
- Свой справочник категорий, брендов, характеристик и значений.
- Первичная загрузка каталога из того, что у магазина уже есть (источник — открытый вопрос).
- Журнал изменений товара, цены и остатка: кто, когда, что.

### 2. Выгрузка на первую площадку

- Соответствия: категория, характеристики и значения, бренд.
- Проверка готовности товара к площадке, список того, чего не хватает.
- Правила цены площадки с округлением.
- Фид по URL и отправка цены и остатка через API.
- Включение и выключение товара на площадке.
- Статус выгрузки и ошибки модерации в разделе «Інтеграції».

### 3. Заказы и отправка

Вместе с этапом 2 — это минимальный запуск продаж на первой площадке.

- Опрос заказов раз в 1–2 минуты, единая лента заказов со всех площадок.
- Резерв остатка при новом заказе, снятие при отмене, рассылка остатка на все площадки.
- Единые статусы заказа в CRM и их соответствие статусам каждой площадки.
- Подтверждение, отмена, смена статуса из CRM с отправкой на площадку.
- Уведомление о новом заказе: Epicentr отменяет заказ, неподтверждённый за 2 часа.
- Накладные Новой Почты: создание из заказа, номер уходит на площадку.

**Запуск продаж на первой площадке.**

### 4. Следующие площадки

Этапы 2–3 для Rozetka, затем для Epicentr. Каталог, правила цен и лента заказов уже есть, добавляются соответствия и клиент API площадки.

### 5. Разделы на потом

Дизайн готовится заранее, реализация после запуска всех площадок:

- **Клієнти** — покупатели из заказов. Данные с площадок неполные: Epicentr, например, показывает покупателя только после подтверждения заказа.
- **Акції** — скидки и акции по каналам, промоакции Rozetka.
- **Аналітика** — продажи по площадкам, товарам, категориям; маржа после комиссии.
- **Контент** — баннеры и страницы витрины. Нужен только с сайтом.

### 6. Сайт-витрина

Строится поверх API CRM по готовому пакету дизайна [`design/`](design/README.md). Для CRM сайт — четвёртый канал продаж: свои цены, свои заказы в общей ленте.

## Открытые вопросы

1. Где сейчас живёт каталог магазина (Excel, кабинет Prom, учётная программа) и сколько в нём артикулов?
2. Есть ли уже кабинеты и продажи на какой-то из площадок?
3. Сколько человек работает в CRM и нужны ли роли (менеджер заказов, контент, владелец)?
4. Только Новая Почта или ещё Укрпошта, Meest, самовывоз?
5. Оплата: наложенный платёж, оплата площадки (Rozetka Pay, Пром-оплата), на счёт?
6. Бывают ли продажи мимо площадок (по телефону, офлайн), которые тоже должны списывать остаток?

Отложено раньше: страховой запас; кто и когда подтверждает заказы; порядок правил цены (бренд или категория); обязательность бренда.
