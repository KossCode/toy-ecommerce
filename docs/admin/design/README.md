# Лапка CRM — пакет дизайна для Stitch

Экраны CRM. Что делает каждый раздел — [`../README.md`](../README.md). Порядок работ — [`../../ROADMAP.md`](../../ROADMAP.md).

Устроен так же, как пакет витрины [`../../design/README.md`](../../design/README.md): один файл — один экран, в конце файла блок `STITCH PROMPT`. Документы на русском, текст на макетах — на украинском, дословно.

## Чем CRM отличается от витрины

Тот же магазин, другой продукт. Общий только шрифт **Manrope** и аккуратность. Витрина тёплая и продаёт, CRM холоднее и работает:

- светло-серый фон вместо тёплой бумаги;
- плотные таблицы, текст 14px, строки около 40px;
- радиус около 8px вместо 12px;
- никаких иллюстраций, мерчандайзинга, шапки магазина;
- коралловый primary витрины не используется для кнопок; он остаётся только в словесном знаке.

Точные значения задаёт [`00-foundation.md`](00-foundation.md).

## Общие данные

Все экраны берут товары, заказы, клиентов, цены и ошибки из [`sample-data.md`](sample-data.md). Новые имена, номера и суммы не выдумывать.

## Оболочка

На каждом экране одна и та же оболочка из фундамента. Навигация:

- Огляд
- Замовлення
- Товари
- Категорії
- Бренди
- Характеристики
- Наявність
- Ціни
- Інтеграції
- *тонкая линия*
- Клієнти
- Акції
- Аналітика
- Контент
- *внизу колонки*
- Налаштування

Верхняя полоса: поиск `Пошук замовлення або артикула`, имя `Олена`, кнопка `Вийти`.

## Как вызывать Stitch

1. Проект Stitch тот же: `6132458022799915653`, «Лапка». Новый проект не создавать.
2. Первым генерировать `00-foundation.md`, `deviceType` `DESKTOP`. Передать дизайн-систему витрины `assets/10632284823089035901`, чтобы взялся шрифт.
3. После принятия фундамента CRM создать из него **отдельную** дизайн-систему Stitch «Лапка CRM» и передавать её id во все экраны CRM. Дизайн-систему витрины для экранов CRM не использовать.
4. В `prompt` класть блок `STITCH PROMPT` целиком.
5. В контекст агента класть файл экрана, `00-foundation.md` и `sample-data.md`.
6. Все экраны CRM — `DESKTOP`, 1440. Мобильной CRM нет: работа идёт за компьютером. Если позже понадобится телефон для подтверждения заказов, это отдельный файл.
7. Если в файле несколько промптов (карточка товара, интеграции), первый — новый экран, следующие — через `edit_screens` того же экрана, если меняется только вкладка.

## Принятые экраны

Пока нет. Принятые картинки кладутся в `approved/` по тем же правилам, что у витрины.

## Что считается принятым экраном

- Та же оболочка, что на фундаменте: навигация, верхняя полоса, таблица, кнопки, чипы статусов.
- Главное действие экрана одно и его видно сразу.
- Статусы подписаны словами, а не только цветом.
- Красный — только ошибка. Не «нет в наличии», не «отменено», не срок.
- Данные из `sample-data.md`, без новых имён и сумм.
- Нет графиков ради графиков: график есть только на «Аналітиці».
