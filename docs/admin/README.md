## Сейчас

### Огляд

Новые заказы и срок подтверждения, заказы к отправке, товары с малым остатком, ошибки площадок.

### Замовлення

- Единая лента со всех каналов. Канал: Rozetka, Epicentr, Prom, **Instagram** (и позже сайт / ручные).
- **Ручное создание:** кнопка «Створити замовлення» — заказы из Instagram Direct и другие вне API площадок. Такой заказ резервирует остаток и учитывается в «доступно» так же, как заказ с площадки; на маркетплейсы уходит обновлённый остаток, но сам заказ на площадку не пушится.
- Фильтры: канал, статус, дата, «потрібно підтвердити».
- Срок подтверждения: Epicentr — 2 часа, Rozetka — 24 часа; у ручных / Instagram — без жёсткого срока площадки.
- Карточка: состав, покупатель, доставка, оплата, история статусов.
- Действия: підтвердити, скасувати з причиною, змінити статус.
- **ТТН Нової Пошти:** в дизайне — номер, статус доставки, создание накладной. Реализация API НП — после запуска продаж ([`../ROADMAP.md`](../ROADMAP.md), этап 5). Пока можно показывать ТТН, если номер уже есть с площадки.

### Товари

- Таблица: артикул, фото, название, бренд, категория, цена, доступно (+ резерв), статус CRM, готовность по площадкам.
- Статус CRM: `Чернетка` (по умолчанию) → `Активний` → `Архів`. Черновик и архив **не** уходят в фиды и API.
- Вкладки: `Усі` · `Чернетки` · `Не на майданчиках` · `Не готові` · `Закінчуються` · …
- Карточка:
  - **Основне:** название (UA), описание (rich text с ограниченными тегами), фото, артикул, категория, бренд, модель, штрихкод, страна, вес, габариты, фиксированные атрибуты из кросс-таблицы (колір, вік, матеріал, тип…).
  - **Ціни і наявність:** базовая и старая цена; наличие смотреть/править удобнее в «Наявність», в карточке — сводка.
  - **Майданчики:** тумблер «Продавати на …»; итог цены; статус модерации; чек-лист обязательных полей. Синк только если `Активний` + тумблер + поля заполнены.
  - **Історія:** кто и когда менял поля, цену, остаток.
- «Дублювати» — для второго цвета/артикула с копированием описания и фото.

Отдельной страницы «товари для синхронізації» нет: статус + тумблеры каналов.

### Категорії

Своё дерево (оно же будущее меню сайта Trio Mio). У каждой категории — маппинг на **листовую** категорию Prom / Rozetka / Epicentr из кэша справочников площадок. Без набора «свободных характеристик категории» в MVP: обязательность полей берётся из кросс-таблицы и из атрибутов смапленной категории площадки (под капотом).

Модель: `categories` → `category_mappings` → `marketplace_categories` (+ кэш атрибутов). Подробнее — [`../integrations/README.md`](../integrations/README.md).

### Бренди

Список брендов и по возможности соответствие справочникам Epicentr/Prom. Если бренда нет у площадки — пометка «потрібно додати через менеджера».

### Наявність

Не журнал приход/расход. Таблица актуальных остатков по артикулам:

| Колонки | Смысл |
| --- | --- |
| Всього | Физический учёт; правится вручную |
| Резерв | В активных заказах (новое / подтверждено, ещё не отправлено) |
| Доступно | `всього − резерв`; это число уходит на площадки |

Ручная правка задаёт новое `всього`. Подпись: новый доступный остаток сразу уходит на все включённые каналы. Черновики видны в списке, но не синкаются.

Логика заказа: новый заказ → резерв ↑ → пуш доступного; отмена → резерв ↓ → пуш; отправка → `всього` и `резерв` ↓ одинаково, доступно не меняется.

### Ціни

Правила цен по площадкам (по умолчанию / категория / бренд / товар). Предпросмотр влияния. В MVP можно упростить UI, модель правил сохраняем.

### Інтеграції

По площадке: последняя выгрузка фида, опрос заказов, отправка цен/остатков; ошибки; очередь повторов; загрузка/обновление справочника категорий (Prom — файл; Rozetka/Epicentr — кнопка обновления по API).

### Налаштування

Пользователи, порог «Закінчується», уведомления о заказах. Позже — отправитель НП. Доступы к площадкам — в «Інтеграціях».

## Что не входит

- Склад с ячейками, закупки, бухгалтерия, журнал приход/расход как учётная книга.
- Отдельный конструктор характеристик и варіанти (group_id).
- Чат с покупателями площадок.
- Настройки только кабинетов площадок: URL фида, тип синхронизации, модерация.
- Платежные системы — будущее.
