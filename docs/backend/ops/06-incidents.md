# Инциденты: что делать

Назад к плану: [`../README.md`](../README.md).

Первое правило: если проблема может задеть живые кабинеты площадок — **сначала остановить запись**, потом разбираться ([`../../integrations/LIVE-ACCOUNTS-SAFETY.md`](../../integrations/LIVE-ACCOUNTS-SAFETY.md) п. 10).

## Как остановить запись в площадки

Быстро, из админки (владелец): «Інтеграції» → площадка → «Вимкнути запис». Режим станет `READ_ONLY`, отправки встанут в `BLOCKED`, опрос заказов продолжит работать.

Если админка недоступна — понизить потолок режима. Параметр меняется с локальной машины (у роли сервера нет права на запись в Parameter Store), затем на сервере пересобирается `.env`:

```bash
# локально
aws ssm put-parameter --profile triomio --name /triomio/prod/app/integrations-max-mode --value READ_ONLY --overwrite

# на сервере (Session Manager)
/opt/triomio/scripts/render-env.sh && cd /opt/triomio && docker compose up -d app
```

Если нужно остановить вообще всё, включая опрос: `docker compose stop app`.

## Сценарии

| Симптом | Первые действия | Дальше |
| --- | --- | --- |
| Админка не открывается | Страница «Оновлюємо систему» → приложение лежит: `docker compose ps`, лог `app` в CloudWatch. Браузер не может соединиться → nginx: `systemctl status nginx`, `nginx -t` | Контейнер не `healthy` → смотреть ошибку старта; после деплоя → `rollback.sh` ([`02-deploy.md`](02-deploy.md) §7) |
| На площадку ушли неправильные остатки или цены | Остановить запись (выше) | По `sync_log` и `audit_log` найти, что и когда ушло; исправить в CRM; вернуть `LIVE` только после «да» владельца |
| Сработал предохранитель массового обнуления | Ничего не отправлять повторно | Выяснить причину (импорт, ошибка опроса, ручная правка); строки `PENDING` подтверждает или отменяет владелец |
| Заказы не приходят | «Інтеграції» → последний опрос и ошибка | `401/403` → ключ отозван или истёк; таймауты → проверить доступность API площадки с сервера |
| Неизвестный статус заказа площадки | Заказ не трогать автоматически | Добавить статус в таблицу маппинга по документации площадки; при сомнении — спросить у площадки |
| Диск заполнен | `df -h`, `docker system df` | `docker image prune -f`; проверить размер логов `json-file`; при росте базы — расширить EBS (без остановки) |
| Память, OOM-перезапуски | аларм `triomio-memory`, `docker stats` | Проверить утечку в логах; временно — снизить `MaxRAMPercentage` или перейти на тип инстанса больше |
| Порча данных, неудачная миграция | Остановить запись, остановить приложение | Восстановление по [`03-backups-restore.md`](03-backups-restore.md) §4.2 |
| Инстанс недоступен | Аларм status check, EC2 → состояние | Автовосстановление; если не помогло — [`03-backups-restore.md`](03-backups-restore.md) §4.3 |
| Сертификат не продлился | `certbot renew --dry-run`, `/var/log/letsencrypt/letsencrypt.log` | [`../aws/04-domain-tls.md`](../aws/04-domain-tls.md) §6 |
| Утёк секрет | — | [`05-security.md`](05-security.md) §6 |
| Резкий рост счёта AWS | Cost Explorer по сервисам | Неизвестные ресурсы или регионы → считать аккаунт скомпрометированным: сменить доступы, проверить CloudTrail |
