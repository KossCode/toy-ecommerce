# Безопасность

Назад к плану: [`../README.md`](../README.md). Общие правила проекта — [`../../../.cursor/rules/workflow-and-secrets.mdc`](../../../.cursor/rules/workflow-and-secrets.mdc); правила работы с живыми кабинетами — [`../../integrations/LIVE-ACCOUNTS-SAFETY.md`](../../integrations/LIVE-ACCOUNTS-SAFETY.md).

Чек-лист. Каждый пункт проверяется до запуска в работу (шаг 11.1).

## 1. Публичный репозиторий

- [ ] В репозитории нет: паролей, токенов, мастер-ключа, `.env` с значениями, ID аккаунта AWS, ARN, ID инстанса, email владельца для root.
- [ ] `.gitignore` содержит `.env`, `.env.*` (кроме `.env.example`), `*.local`, `*.dump`, `*.pem`.
- [ ] gitleaks в CI на каждом PR ([`../10-testing.md`](../10-testing.md) §4).
- [ ] ID аккаунта, ARN ролей, ID инстанса — только в GitHub Environment Variables окружения `production`.
- [ ] Реальные ответы API площадок с данными покупателей не попадают в тестовые фикстуры.

## 2. Аккаунт AWS

- [ ] Root с MFA, без access keys ([`../aws/01-account-setup.md`](../aws/01-account-setup.md) §3).
- [ ] Вход людей — через Identity Center с MFA.
- [ ] Ни одного IAM-пользователя с access keys; GitHub — через OIDC.
- [ ] Роль EC2 ограничена своими бакетами, параметрами и топиком ([`../aws/03-s3-iam-ssm.md`](../aws/03-s3-iam-ssm.md) §3).
- [ ] Бюджеты и Cost Anomaly Detection включены — взлом аккаунта часто первым виден по счёту.

## 3. Сеть и сервер

- [ ] Security group: только 80 и 443 (до покупки домена — ничего).
- [ ] SSH закрыт; вход только Session Manager; сессии логируются в CloudTrail.
- [ ] IMDSv2 обязателен.
- [ ] EBS зашифрован; бакеты с SSE-S3.
- [ ] PostgreSQL и порт приложения не опубликованы наружу.
- [ ] `unattended-upgrades` включён, перезагрузка ночью.
- [ ] Образы с конкретными версиями, а не `latest`; пересборка образа приложения не реже раза в месяц, чтобы подтянуть исправления базового образа.

## 4. Приложение

- [ ] Все `/api/**`, кроме входа, требуют сессию; права проверяются на сервере ([`../06-auth-and-roles.md`](../06-auth-and-roles.md) §3).
- [ ] CSRF включён; cookie `HttpOnly`, `Secure`, `SameSite=Lax`.
- [ ] Ограничение попыток входа.
- [ ] `/actuator/**` закрыт в nginx; OpenAPI UI выключен в prod.
- [ ] Ошибки `500` не отдают стек и SQL.
- [ ] Загрузка файлов: проверка типа по содержимому и размера ([`../09-media-s3.md`](../09-media-s3.md) §3).
- [ ] HTML в описаниях товаров санитизируется по белому списку тегов Epicentr (`p`, `br`, `b`, `ul`, `li`, `table`, `tr`, `td`) — защита админки от XSS и требование площадки одновременно.
- [ ] Ключи площадок зашифрованы в базе, наружу — только маска ([`../08-marketplace-sync.md`](../08-marketplace-sync.md) §5).
- [ ] Чувствительные действия пишутся в `audit_log`: смена режима записи, ключей, ролей, сброс паролей, массовые операции.
- [ ] Dependabot для Maven, npm, Docker, GitHub Actions; критичные уязвимости закрываются в течение недели.

## 5. Персональные данные покупателей

Из заказов приходят имя, телефон, адрес доставки.

- [ ] Доступ — только у авторизованных пользователей CRM.
- [ ] В логах телефон маскируется (`+380*****1234`), адрес и имя не пишутся.
- [ ] В `sync_log` хранятся только выдержки ответов без персональных данных.
- [ ] Срок хранения задан владельцем ([`../README.md`](../README.md) §6, вопрос 5); по истечении — обезличивание (`customer_name`, `customer_phone`, `delivery_address`, `raw_payload` очищаются), заказ и суммы остаются для статистики. Решение от 22.10.2026: пока храним без срока; срок нужно задать до запуска продаж через CRM.
- [ ] Дампы базы содержат персональные данные: бакет `backups` закрыт, шифрован, со сроками хранения.

## 6. Если секрет утёк

| Что утекло | Действия |
| --- | --- |
| Ключ площадки | Создать новый ключ в кабинете площадки → сохранить в CRM → отозвать старый → проверить историю изменений в кабинете площадки (наш `sync_log` чужих вызовов не покажет) |
| Мастер-ключ шифрования | Новый мастер-ключ в Parameter Store → команда перешифровки ключей площадок → перезапуск → заменить ключи площадок (они могли быть расшифрованы) |
| Пароль БД | Новый пароль в Parameter Store → `ALTER USER triomio PASSWORD ...` → `render-env.sh` → перезапуск приложения |
| Пароль пользователя CRM | Сброс владельцем; завершить сессии пользователя (удаление строк в `spring_session`) |
| Секрет закоммичен в git | Считать скомпрометированным сразу: ротировать по строкам выше. Удаление из истории — вторично, репозиторий публичный и мог быть склонирован |
