# Фото товаров (S3)

Назад к плану: [`README.md`](README.md). Создание бакета — [`aws/03-s3-iam-ssm.md`](aws/03-s3-iam-ssm.md) §1. Требования площадок к фото — [`../integrations/README.md`](../integrations/README.md), «Поля, которые передать нельзя или можно частично».

## 1. Зачем публичный доступ

Площадки скачивают фото по URL из фида. Поэтому фото товаров должны открываться без авторизации. Публичен только префикс `products/` в бакете `media`; всё остальное в бакете закрыто.

CloudFront не используем ([`README.md`](README.md) §1): площадки скачивают каждое фото один раз, трафик небольшой. Когда появится сайт-витрина, отдавать фото покупателям через CloudFront станет дешевле и быстрее — тогда и подключим.

## 2. Хранилище за интерфейсом

```java
public interface MediaStorage {
    StoredObject put(String key, InputStream data, long size, String contentType);
    void delete(String key);
    URI publicUrl(String key);
}
```

| Профиль | Реализация | Где лежат файлы | Публичный URL |
| --- | --- | --- | --- |
| `local` | `LocalDiskMediaStorage` | `./.local-media/` | `http://localhost:8080/media/...` |
| `prod` | `S3MediaStorage` (AWS SDK v2) | бакет `media` | `https://<bucket>.s3.eu-central-1.amazonaws.com/products/...` |

Доступ к S3 — по instance role EC2; ключей в конфиге нет.

## 3. Загрузка

1. Админка отправляет файл `multipart/form-data` на `POST /api/products/{sku}/images`.
2. Бэкенд проверяет:
   - тип по содержимому файла, а не по расширению: JPEG, PNG или WebP;
   - размер — до 10 MB;
   - не больше 15 фото на товар (максимум Rozetka; Prom берёт первые 10).
3. Ключ: `products/{sku}/{uuid}.{ext}`. UUID в имени делает объект неизменяемым: замена фото = новый объект, старые ссылки в фидах не «подменяются».
4. Запись в `product_images` с позицией в конце списка.

Через бэкенд, а не presigned URL из браузера: файлы небольшие, а проверка и запись в базу в одном месте проще. Если загрузка начнёт упираться в память или время — переходим на presigned `PUT`.

## 4. Порядок и удаление

- Первое фото — главное; площадки требуют белый фон и без надписей. Порядок меняется `PATCH /api/products/{sku}/images/order`.
- Удаление убирает строку из `product_images` и объект из S3. Версионирование бакета хранит удалённую версию 30 дней на случай ошибки ([`ops/03-backups-restore.md`](ops/03-backups-restore.md) §5).
- При «Дублювати» товар-копия ссылается на те же объекты; объект удаляется из S3, только когда на него не осталось ссылок.

## 5. Что не делаем в MVP

- Генерацию превью и пережатие: админке хватает оригинала с `loading="lazy"`. Вернёмся, если списки товаров станут медленными.
- Водяные знаки и бейджи на фото — площадки их запрещают.
