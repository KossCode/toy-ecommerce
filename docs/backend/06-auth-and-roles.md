# Авторизация и роли

Назад к плану: [`README.md`](README.md). Экран входа — [`../admin/design/13-login.md`](../admin/design/13-login.md).

## 1. Схема

- Логин по email и паролю, Spring Security, форма входа своя (SPA), API — `POST /api/auth/login`.
- Сессия на сервере, хранится в PostgreSQL через Spring Session JDBC. Поэтому деплой и перезапуск не разлогинивают пользователей.
- Cookie `SESSION`: `HttpOnly`, `Secure`, `SameSite=Lax`, путь `/`.
- Таймаут неактивности — 12 часов. Срок жизни сессии ограничиваем 7 днями: после этого вход заново.
- После входа ID сессии меняется (защита от session fixation, включена в Spring Security по умолчанию).
- CSRF-защита включена: `CookieCsrfTokenRepository` + заголовок `X-XSRF-TOKEN` ([`05-api.md`](05-api.md) §4).

## 2. Пароли

- Хеш: `DelegatingPasswordEncoder` Spring Security (по умолчанию bcrypt). Префикс алгоритма в хеше позволяет позже сменить алгоритм без массового сброса паролей.
- Минимальная длина — 12 символов; проверка по списку самых частых паролей.
- Восстановления по почте в MVP нет. Пароль менеджера сбрасывает владелец: генерируется временный, при входе обязательна смена (`must_change_password`). Пароль владельца сбрасывается командой на сервере (§4).

## 3. Роли

Предложение для MVP — две роли. Окончательный состав подтверждает владелец ([`README.md`](README.md) §6, вопрос 3).

| Действие | Власник (`OWNER`) | Менеджер (`MANAGER`) |
| --- | --- | --- |
| Заказы: смотреть, создавать ручные, подтверждать, отменять, вводить ТТН | да | да |
| Товары, категории, бренды: смотреть и редактировать | да | да |
| Остатки: ручная правка | да | да |
| Правила цен | да | только смотреть |
| Інтеграції: смотреть статус, повторить ошибки | да | да |
| Інтеграції: сменить режим записи, ключи площадок, запустить джобу | да | нет |
| Пользователи: создать, отключить, сбросить пароль | да | нет |
| Налаштування | да | только смотреть |

Проверка — аннотациями `@PreAuthorize` на сервисах, а не только скрытием кнопок в админке. Каждая строка матрицы покрыта тестом (шаг 6.2).

## 4. Первый владелец

В репозитории нет ни логинов, ни хешей — он публичный. Первый пользователь создаётся командой на сервере через Session Manager:

```bash
cd /opt/triomio
docker compose run --rm app create-owner --email owner@<domain>
```

Команда выводит временный пароль один раз; при первом входе он меняется. Та же команда с `--reset` сбрасывает пароль существующего владельца.

## 5. Защита от перебора

- Не больше 5 неудачных попыток за 15 минут для пары «email + IP». Дальше — `429` на 15 минут.
- Ответ на неверный email и неверный пароль одинаковый, по тексту и по времени.
- Все входы, неудачные попытки, смены паролей и ролей пишутся в `audit_log` (`kind = Користувачі`).
- Реальный IP клиента приходит от Caddy в `X-Forwarded-For`; Spring доверяет этому заголовку только от адреса Caddy внутри Docker-сети.

## 6. Что не входит в MVP

- Двухфакторная аутентификация для пользователей CRM (кандидат на добавление сразу после запуска — для владельца).
- Вход через Google и SSO.
- Учётки покупателей сайта — отдельная тема вместе с сайтом.
